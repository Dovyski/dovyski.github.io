Fourteen steps before
the first line of code.
The same fourteen, every issue.

Clone, branch, draft pull request, two databases, a local site, an .env, dependencies, migrations. Done by hand, one step gets skipped — often the cache prefix, and then two clones quietly share keys in the same Redis. o turns the routine into commands, and the commands into something an agent can run as well as a person.

Workspace

One issue.
One folder, ready to run.

o work reads the issue, clones the repository into its own folder, branches, opens a draft pull request linked to the issue and builds the app against fresh databases. Every clone gets its own identity, so ten of them can run side by side.

Hotfix from the release tag

--from takes a branch, a tag or a commit. A hotfix starts from what production runs, the last release tag, and targets main with --to.

Host-coupled keys follow

With --herd, APP_URL is set to the clone's HTTPS site and every other key carrying the example's .test host is rewritten. Shared hosts like localhost are left alone.

Tests included

A _test database and an .env.testing pointing at it are created, migrated and seeded with the rest. o db does the same on its own.

Import retries

Each row is posted to the partner API in batches of 200. The importer retries three times and then drops the row silently before giving up on the batch.

Retries back off by 2, 4 and 8 seconds. A batch that fails three times is moved to the dead-letter table.

Invisible everywhere else

Anchors and comments are HTML comments, so GitHub, editors and formatters ignore them. Everything that is not an annotation stays byte-identical.

Threads that keep their number

Replies share the thread's id, and the file records the next id to hand out, so a deleted thread is never renumbered into someone else's.

Code and diagrams too

Fenced code is highlighted by language and can be commented by line and column. Mermaid blocks render as diagrams. --strip leaves a clean document.

Release

Two pull requests,
one tag, no clicking.

Every repository follows the same branch flow, so releasing is the same few steps everywhere. o runs them in order, waits where it has to, and prints the links when it is done.

  • To stage. o version stage opens the main → dev sync and the dev → main pull request; CI takes it from there.
  • To production. o release also merges both once branch protection allows it, then tags vYYYY.MM.DD.HHMM with the minute rounded to five.
  • Resumable. A failed merge stops before the tag and prints what was created. --skip-merges picks up from there; --skip-release syncs without tagging.
Shell

A shell in any container.
Stage or production.

o ssh goes through each environment's bastion. On stage the target is a container name; on the Kubernetes clusters it is namespace/workload, and the bastion picks a ready pod of that Deployment or Rollout for you.

sshstagekey~/.ssh/id_ed25519

Onboarding in one command

o ssh setup reuses or generates an ed25519 key, publishes it to GitHub through gh, then tries the bastion and explains what a failure means.

The right key, every time

ssh offers agent keys first and can run out of attempts before yours. o pins the managed key as the only identity offered.

Checked on both ends

Targets are validated before ssh starts, in either form, and the bastion validates them again before it opens a shell.

Vault

Secrets that stay
off the screen.

The team's credentials live in a server-side vault. Listings show names, formats and clearance levels, never values. Revealing one takes a six-digit code from your phone.

  • Clipboard, not scrollback. Text secrets are copied, never printed. Markdown runbooks are rendered in the terminal.
  • People reveal, scripts write. Without an interactive terminal, get refuses. set reads stdin and has no --value flag to leak into shell history.
  • One code per burst. The code buys a vault token of about ten minutes, cached encrypted.

Exceptions name the rule

// o:ignore method-length <reason> excuses one declaration. There is no blanket or file-wide ignore, and a directive that cannot apply is itself reported.

Annotations on the diff

--format=github-action turns findings into warnings on the pull request; --fail-on makes chosen rules block the build.

One run is enough

Rewrites repeat over their own output until nothing changes, so a second run finds nothing new. --pint runs Pint before and after.

Board

Your board,
in the terminal.

o tasks streams what is assigned to you, board by board, with each board's own statuses. o issue create and o issue update set the type, the issue fields and the board fields in one call, and check every value before they write anything.

tasksgh

Live work first

By default only TODO, DOING, TESTING and REDO show. --everyone turns it into the team's triage view; --table and --json are there for scripts.

Names, not IDs

Fields and options are resolved by name and cached for a day. A typo fails before the issue exists, with the board's valid options in the message.

Plans before writes

--dry-run shows each field's current and new value. o issue fields prints the whole schema a repository's board accepts.
